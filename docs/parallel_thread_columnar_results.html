测量口径与边界

  • 先完成三组各五轮旧新交替测量；运行时复查后的最终代码再分别复测五轮，表中旧版指标引用已完成的原五轮，最终版与旧版不是同轮交替执行。未与测试或构建并行。
  • 仅采样本次子进程及后代；CPU 为累计 CPU 秒，不是全机占用百分比。RSS 为各进程工作集之和，含重复映射页，并非独占物理内存。单位 MiB。
  • 探测与配置加载在计时前；cold 含预热、JIT 编译/缓存加载和首次建连，warm 复用执行器、目录与连接。最终版一万任务首轮 cold 为 21.94 秒；后四轮缓存 cold 中位数 7.76 秒。部分冷批次发生 chunk 重试，不能把全部差额视为 JIT 编译耗时，也不能据热启动结果承诺首次调用同样耗时。
  • 一万任务热批次，列式抓取阶段累计线程 CPU 中位数约 1.98 秒，行对象打包约 1.89 秒；这些是线程累计值，不等于端到端墙钟，也不包含全部入口调度开销。

单 host 小批次热启动耗时退步：新单站参数约束实际工作连接，旧进程配额还可叠加进程内并发。没有为追求速度放宽该保护。结果仍保留行对象，因此一万任务内存降幅未达一半；CPU 总时间也未达旧版 10%。

ZIP 思路的工程落地

  • 借鉴释放 GIL 的有界解码、零拷贝输入、NumPy 列、覆盖即停分页、去重与闭区间切片；分钟线、指数、板块、港股和期货按本工程协议补齐。
  • 保留原任务分桶与稳定排序、host 探测排序、多站均衡、请求恢复阶梯、chunk 重试、自适应降配额和冷却恢复。收发失败先废弃连接，完整空响应与传输失败分开处理。
  • 没有照搬 Demo 的日线专用格式、UTC+8 假设、环境版本锁定、简化冷却策略及同站超配。旧进程 YAML 字段移除，使用 thread_workers 与 threads_per_host_std/ex；worker_pid 移除。
  • 预热集中编译且不连业务站；重启先中断旧 socket 并等待真实回收。原生扩展或解释器死锁仍需外部重启，无法安全强杀 Python 线程。

后续 simple_api 列式交付

当前正式内核产物为只读 NumPy 列页，分页合并与窗口切片持有有效数组引用；现有行格式只在独立交付适配层构造。没有提前改变公开返回格式。

后续队列可直接交付列式批次，把 DataFrame、字典和其他格式打包留给用户侧。启用前需明确 schema 版本、字段/dtype、有效行数、时间单位与时区、缺失值、数组所有权/生命周期及回调协议，再单独修改公开契约。

现有验证覆盖所列样本和故障场景，不能证明所有服务器回包和所有 Python/操作系统组合永远无缺陷。wheel/sdist 构建及提取 wheel 的导入、解码预热、执行器回收冒烟已通过；未提交、推送或发布。
