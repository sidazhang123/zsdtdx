# 多线程与列式 K 线实施计划

## 基线与目标

- 基线提交：143da95（2.4.0）。移除全部进程池执行路径，股票、指数、板块、期货和公司信息统一使用有界线程执行。
- 准确性与业务稳健性为硬门槛；耗时、内存约减半和 CPU 总时间约为旧版 10% 是优化目标，不以减少保护换取。
- 网络和任务故障必须有界收敛；解释器或原生扩展死锁需要外部重启整个进程。

## 执行与契约

1. 保留任务分桶、稳定排序、重复任务逐项交付及多窗口分页复用。
2. 全局线程预算和标准/扩展侧单站配额分离，换站同样必须取得目标站准入，配额在工作实际停止后释放。
3. 保留请求恢复层级、chunk 重试、自适应降配额与冷却恢复；半包和传输失败必须废弃污染连接。
4. 截止时间使用单调时钟，覆盖建连、握手、分段收发及恢复；超时关闭 socket，禁止旧尝试继续创建连接。
5. 保留公开函数、任务句柄、回调、行情字段、data/done 和错误统计；删除 worker_pid，生命周期摘要改报线程与连接。
6. 重启和销毁结算未完成任务，隔离旧代结果；禁止通过反复重建执行器突破全局资源预算。
7. YAML 改用 thread_workers（默认 44）、threads_per_host_std/ex（默认 4），保留提交窗口、超时、重试和拥塞参数；删除旧进程配置别名。

## 列式内核与交付边界

1. 回包、解压、numba 解码、分页缓存、过滤去重排序和窗口切片全程列式，内核不构造行字典、日期字符串或 DataFrame。
2. 覆盖标准差分、指数涨跌家数、板块绝对价、扩展固定记录及全部现有周期和复权设置。
3. 数组归作业所有，交付引用保持有效，不可被后续任务覆盖；内部共享数组只读。
4. 列式结果是正式内核产物；本次由独立适配层转换为既有 rows / DataFrame，保留回调契约。
5. 暂不新增对外输出模式。后续可让 simple_api 队列直接交付列式结果，由用户侧打包；字段、dtype、有效行数、时间单位/时区及缺失值需形成明确契约。

## ZIP 研究与踩坑逐项落实

- numba 内核释放 GIL，关闭 fastmath，不嵌套并行；编译函数内部不 import。
- 保留量能 get_volume 历史分支、浮点运算顺序和 np.round / np.rint 行为。
- 字符串与 Python 对象构造移至交付边缘，分开统计其耗时。
- 检查包长、记录数和变长整数边界；慢回包不能重置累计截止时间，半包必须断连。
- host 上限为真实硬约束，不照搬 Demo 的超配和仅建连失败计数。
- 时间语义与既有实现对拍，不固定 UTC+8，覆盖历史夏令时及带时区输入。
- numba 按需加载、集中预热并缓存；声明正式依赖，不复制 Demo 的路径和无关环境版本约束。
- 按本次进程树测量 CPU、内存，区分探测、冷启动、预热、格式转换和结果驻留成本。

## 实施与验收

1. 固定基线回归与样本；实现列式结构及各协议内核并离线对拍。
2. 实现线程执行、截止时间和 host 准入，接入所有业务入口及生命周期。
3. 删除旧执行链，更新配置、中文文档、脚本和经批准改变的诊断断言。
4. 固定回包逐字段/类型及浮点位级对拍；检查输入任务数量，防止两端同时漏任务的假通过。
5. 覆盖短读、半包、滴流、握手失败、坏包、单站/全站故障、并发调用、重启、销毁和持续资源回收。
6. 同机旧新交替至少五轮，区分冷/热启动，对比 Demo 一万任务、全市场单窗口、多周期及长历史；分别报告内核与格式交付成本。
